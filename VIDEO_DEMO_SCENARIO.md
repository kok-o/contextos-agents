# ContextOS vs Vanilla AI: Сценарий видео-демонстрации и бенчмарка

> **Цель видео**: Наглядно показать драматическую разницу между «ванильным» AI-агентом (Cursor, сырой Claude/Gemini) и **ContextOS с оркестрацией субагентов**.  
> **Формат**: Split-Screen (разделенный экран: слева — Vanilla AI, справа — ContextOS), хронометраж ~3–4 минуты или динамичный 60–90 сек шортс.  
> **Целевая аудитория**: VP of Engineering, Tech Leads, Senior Developers, CISO, энтузиасты AI-разработки.

---

## 1. Главные контрасты для видео (The "Day & Night" Effect)

| Критерий | Vanilla AI (Без ContextOS) | ContextOS + Subagents |
| :--- | :--- | :--- |
| **Архитектура процесса** | Линейная простыня промптов в одном чате | Ролевая декомпозиция (`Architect` → параллельные субагенты) |
| **Параллельность** | 1 медленный поток, файл за файлом | **3 независимых субагента** работают одновременно |
| **Качество кода** | Заглушки (`// TODO: implement later`, mock-данные) | **100% Zero-Placeholder** production-ready код |
| **Безопасность и границы** | Нарушает чужой код (uncontrolled blast radius) | Строгие границы скоупа (**Zero File Overlap**) |
| **Верификация** | «Вроде работает» (галлюцинация успеха) | **Детерминированный Quality Gate** (`npm test`, линтеры) |
| **FinOps (Token Burn)** | Сканирует весь репозиторий, жжет x2–x3 токенов | Таргетированный контекст, **экономия до 50–60% токенов** |

## 2. Три варианта задач для демонстрации

### Вариант 1 (Главный фаворит): «Webhook Ingestion & Idempotency Pipeline + Live Monitor»

*Полноценный Full-Stack модуль уровня Stripe/GitHub с защитой от повторов и живой панелью мониторинга.*

* **Архитектурный скоуп**:
  1. **Backend & Security**: Эндпоинт приема вебхуков, криптографическая проверка HMAC-подписи с защитой от timing attack (`crypto.timingSafeEqual`), дедупликация через idempotency keys с TTL.
  2. **Frontend UI**: Панель мониторинга с карточками метрик, фильтром статусов (`Received`, `Processed`, `Duplicate_Rejected`, `Invalid_Signature`), просмотром тела запроса и кнопкой «Повторить (Retry)».
  3. **QA & Tests**: Стресс-тест на состояние гонки (race conditions) при параллельных одинаковых вебхуках и тесты на отказ при битой подписи.
* **Почему идеален для видео**:
  * Обычный агент делает HMAC через простой `===` (дыра безопасности), забывает про идемпотентность или оставляет `// TODO`, рисует примитивную серую таблицу.
  * ContextOS оркестрирует 3 субагента: один берет бекенд и безопасность, второй собирает UI по дизайн-токенам (`impeccable-design`), третий пишет падающие тесты и проверяет зеленую сборку.

* **Архитектурный скоуп**:
  1. **Core**: Алгоритм Token Bucket с скользящим окном и заголовками `X-RateLimit-*`.
  2. **UI**: Виджет потребления токенов с прогресс-баром бюджета и алертами.
  3. **Tests**: Тестирование граничных значений и переполнения лимита.
* **Контраст в видео**:
  * Обычный агент делает наивный `setInterval` в памяти (утечка памяти) и падает при запуске в кластере.
  * ContextOS применяет правила `ponytail-mindset` (минимализм без лишних зависимостей) + строгую типизацию.

### Вариант 3: «Хирургический фикс состояния гонки (Race Condition) в легаси-коде»

*Сценарий на точность (Surgical Blast Radius) на основе [benchmarks/gemini-issues.js](file:///c:/Users/esenb/Desktop/my_geni/benchmarks/gemini-issues.js).*

* **Архитектурный скоуп**:

* **Контраст в видео**:
  * Обычный агент переписывает файлы целиком, стирает комментарии и ломает соседние тесты.
  * ContextOS локализует баг, субагент-тестировщик фиксирует сбой тестом, разработчик применяет точечный патч в 4 строки без побочных эффектов.

## 5. Готовые промпты для съемки

### Промпт для Vanilla AI (Левый экран)
```text
Реализуй модуль приема вебхуков для нашего приложения.
Нужно:
1. Защита от дубликатов (идемпотентность по заголовку Idempotency-Key).
2. Проверка подписи HMAC SHA-256 из заголовка X-Signature.
3. Веб-интерфейс для просмотра полученных хуков и статусов обработки.
4. Набор тестов.
Сделай всё прямо сейчас.
```

### Оркестрирующий запуск ContextOS (Правый экран)

**Шаг 1. Промпт ведущему агенту**:
```text
[DOMAIN: Full-Stack] [PHASE: Plan] [ROLE: Architect]
Задача: Реализовать модуль Webhook Ingestion с идемпотентностью, HMAC-верификацией, BDD тестами и монитор-дашбордом.
Используй skill: subagent-orchestrator.
Сформируй TaskBrief с тремя непересекающимися зонами (Blast Radius) и делегируй реализацию параллельным субагентам.
```

**Шаг 2. Контракты для субагентов (выполняются оркестратором автоматически)**:

* **Субагент 1 (Backend & Security)**:
  * *Write Scope*: `src/server/webhooks/*`
  * *Задачи*: HMAC verification via `crypto.timingSafeEqual`, in-memory idempotency store with TTL, JSON payload parsing.
  * *Quality Gate*: `npm run test:backend`
* **Субагент 2 (Frontend UI)**:
  * *Write Scope*: `src/client/components/webhooks/*`
  * *Правила*: `impeccable-design`, `ui-ux-pro`, семантические токены, empty states, latency badges.
  * *Quality Gate*: `npm run build:client`
* **Субагент 3 (QA Lead)**:
  * *Write Scope*: `tests/webhooks/*`
  * *Задачи*: TDD сьют: replay attack test, invalid secret signature test, concurrent duplicate payload lock test.
  * *Quality Gate*: `node --test tests/webhooks/*.test.js`
