# GPT-6 Luna: проверка ContextOS на задачах репозитория

**Отложено пользователем 1 октября 2026 года из-за проблем с API.**
Платные и новые benchmark-прогоны не продолжать до явного запроса пользователя.
Сохранённые результаты, исходники и spending ledger оставить для продолжения.

Статус: локальный протокол реализован и проверен. Пилот остановлен дневным
лимитом API, завершены две сравнимые задачи во всех трёх ветках. Реальный
Codex CLI включил тела явно указанных навыков в исходящий payload; это
проверено локальным capture без inference. Ответ модели по нативным навыкам
и полный агентный прогон пока не подтверждены.

## Что измеряется

Двадцать контролируемых регрессий в четырёх настоящих модулях ContextOS:

| Модуль | Задач | Проверяемые контракты |
| --- | ---: | --- |
| Разбор аргументов resolver | 5 | Флаги, файлы, бюджет, отсутствующие значения, разделитель |
| Учёт usage | 5 | Неизвестные значения, Responses, кеш, допустимые числа, агрегаты |
| Безопасность путей | 5 | NUL, ADS, устройства Windows, корень, выход за границы |
| Граф рабочего пространства | 5 | Клоны, вложенные репозитории, workspace, предел, зависимости |

Это **seeded-repository-regression**, а не двадцать исторических багов или
двадцать независимых проектов. Набор нужен для калибровки инструментария и
сравнения поведения в этих модулях. Для выводов о реальной пользе необходим
отдельный набор внешних задач и пилот из `PILOT_PROTOCOL.md`.

Для каждой задачи сохранены хеши оригинального исходника и версии с ошибкой.
До платных запросов проверяются две контрольные версии: оригинал проходит
скрытые контракты модуля, внесённая ошибка их нарушает. Несовпадение исходника с
ожидаемым фрагментом или провал контроля останавливает запуск.

## Сравнение

Одинаковая модель `gpt-6-luna`, Responses API, reasoning `medium`, Standard,
4096 выходных токенов на запрос и максимум шесть запросов на попытку:

1. `arm-a-vanilla`: нейтральная инженерная инструкция.
2. `full-installed`: все 11 установленных entrypoint: семь core и четыре catalog.
3. `arm-c-contextos-core`: выбор каноническим resolver из той же установки.

Catalog в рабочем checkout не считается установкой. Для сравнения создаётся
отдельная consumer-копия. Во всех ветках одинаковые задача, доступные файлы,
инструменты, лимиты и скрытые проверки. Порядок веток циклически меняется.

Агент читает файлы, применяет точечные правки и проверяет синтаксис JavaScript.
Он не видит правильного исходника, внесённой мутации или скрытых assertions.
Итоговая проверка выполняет все пять контрактов соответствующего модуля,
включая соседние функции. Это не полный регрессионный suite всего продукта.

Пилот: три задачи, три ветки, один повтор — девять попыток. Полный запуск:
20 × 3 × 3 = 180 попыток, до 1080 HTTP-запросов. Полный запуск требует успешного
протокольного пилота с теми же исходниками и controller. Пилот добавляется к
полным 180 попыткам; его результаты не подменяют три повтора полного набора.

## Безопасность и бюджет

Инструменты допускают чтение только списка файлов и запись только целевого
файла. Нельзя читать controller, скрытые тесты, конфигурацию пользователя или
другие файлы; нет произвольного shell, сетевых и делегирующих инструментов.

Изменённый код запускается в отдельном Node-процессе с permission model,
ограниченным loader, запретом генерации кода из строк, пределом памяти и
тайм-аутом. Запись разрешена только в отдельные тестовые данные. Ключи не
передаются этому процессу. Эти ограничения проверены отрицательными тестами;
Node VM сам по себе не является границей безопасности для произвольного
враждебного кода. Для внешнего недоверенного корпуса нужен контейнер или VM.

Согласованный общий лимит — **$10**, включая прежние GPT-4.1-mini запуски.
На момент подготовки прежний консервативный резерв составляет $2.836962,
остаётся $7.163038. Runner использует тот же ledger и эксклюзивный `run.lock`.
Это лимит данного runner, а не других расходов OpenAI-проекта.

До каждого HTTP-запроса сохраняется резерв по байтовой верхней оценке текста,
протокольному запасу, максимальному выходу и 25% запасу цены. Учитывается
максимальная короткая цена cache write; Fast и региональные тарифы не
используются. Только завершённый ответ с допустимыми provider usage позволяет
сократить резерв до консервативной верхней стоимости. Ошибки, тайм-ауты,
неполные ответы и неизвестная стоимость сохраняют резерв. Reasoning не
прибавляется второй раз к выходным токенам.

Цены за миллион токенов: input $0.10, cached input $0.01, cache write $0.125,
output $0.50. Источник: [официальная модель](https://developers.openai.com/api/docs/models/gpt-6-luna),
проверено 30 сентября 2026 года. `standardRateEstimateUsd` — оценка по usage;
если provider не сообщает cache writes, это не точная сумма счёта.

Ключ вводится маскированно через PowerShell, хранится в памяти процесса и
удаляется из временного environment по завершении. URL фиксирован на
`https://api.openai.com/v1/responses`, HTTP redirects запрещены. Автоматических
повторов платных запросов нет. Первая ошибка API останавливает запуск.
До HTTP применяется регулируемый темп по оценке размера запроса. По умолчанию
используются наблюдавшиеся 60 000 TPM; это оценка, а не гарантия отсутствия 429
при других запросах в том же проекте. Для подтверждённого более высокого
лимита можно передать `-Tpm 600000`. Этот параметр не меняет денежный лимит.

## Команды

Из корня проекта, без ключа и платных запросов:

```powershell
node --test tests/luna-agent-benchmark.test.js
node benchmarks/run-luna-agent.js --controls-only
node benchmarks/run-luna-native.js --capture-only
& .\benchmarks\run-luna-agent.ps1 -PreflightOnly
```

Платный пилот с маскированным вводом ключа:

```powershell
& .\benchmarks\run-luna-agent.ps1 -Mode pilot
```

После завершённого пилота:

```powershell
& .\benchmarks\run-luna-agent.ps1 -Mode full
```

После устранения ошибки доступа или лимитов можно продолжить конкретный запуск:

```powershell
& .\benchmarks\run-luna-agent.ps1 -Mode pilot -Resume RUN_ID
```

Замените `RUN_ID` именем каталога из сообщения `Report`. Успешно обработанные
попытки повторно не оплачиваются; ошибки API сохраняются в истории, их новые
попытки требуют нового резерва. Drift исходников, контекста или controller
запрещает resume. Отсутствующие файлы и аварийный выход не дают права удалять
spending ledger или неизвестные резервы.

## Нативная активация Codex

Отдельная проверка запускает установленный `codex exec` в изолированной
фикстуре и временном `CODEX_HOME`. Она явно вызывает `engineering-workflow`
и специальный навык с случайным маркером, находящимся только в его теле.

```powershell
& .\benchmarks\run-luna-agent.ps1 -Mode native -PreflightOnly
& .\benchmarks\run-luna-agent.ps1 -Mode native
```

CLI получает только случайный локальный proxy token. Реальный API-ключ
остаётся в родительском процессе. Локальный gateway пропускает максимум шесть
Responses-запросов, каждый через общий spending guard. Он ограничивает модель,
тариф, контекст и выход, сохраняет SSE completion/usage и не допускает платные
встроенные инструменты. User config, rules и auth не изменяются; subprocess
использует read-only sandbox и ephemeral-сессию.

PASS требует, чтобы реальный API payload содержал тела обоих навыков, CLI
вернул неизвестный ему заранее маркер, а события не содержали shell, правок,
MCP или web-действий. Preparation и metadata discovery сами по себе не PASS.
Такой результат подтверждает явную активацию в данном Codex CLI; он не
доказывает автоматическую маршрутизацию, соблюдение правил на сложных задачах
или загрузку навыков Cursor.

## Артефакты и интерпретация

Результаты агентного прогона: `scratch/luna-benchmark/RUN_ID/report.json`.
Для каждой попытки сохраняются исходник до/после, оригинальные Responses,
usage, инструменты, время, контекстные хеши и итог скрытых тестов.
Нативный тест: `scratch/luna-native/native-*/report.json`, request payloads,
SSE, JSONL события и диагностика CLI. Проверки до API:
`scratch/luna-benchmark/controls.json` и `preflight.json`.

Качество сравнивается на полных тройках task/repetition. Ошибки API и
инфраструктуры учитываются отдельно; достижение лимита шагов считается
неудачной попыткой модели и не удаляет тройку из сравнения. Сравнивайте долю
исправлений без соседних регрессий, входные/кешированные/выходные токены,
стоимость, время и вызовы инструментов. Из-за четырёх общих модулей и
повторяющихся задач 180 попыток не являются 180 независимыми наблюдениями.

Не заявляйте универсальный выигрыш, если focused лишь дешевле full-installed,
но не превосходит vanilla по качеству или цене. Сначала изучите провалы и
причины выбора навыков, затем решайте, нужен ли внешний набор сложнее.
